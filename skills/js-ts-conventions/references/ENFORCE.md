## What enforce.py writes

| File | Owner | Notes |
|---|---|---|
| `.js-ts-conventions/plugin.mjs` | generated | Custom rules (`js-ts-conventions/*`), zero dependencies, shared by both linters |
| `.js-ts-conventions/oxlint.json` (`oxlint.<pkg>.json` per extra unit) | generated | The config `.oxlintrc.json` extends |
| `.js-ts-conventions/eslint.mjs` | generated | `withConventions()` wrapper |
| `.js-ts-conventions/legacy.json` | generated by `--ratchet` | oxlint files frozen per rule |
| `.js-ts-conventions/manifest.json` | generated | SHA per generated file, plus the `--agents` choice |
| `.js-ts-conventions/README.md` | generated | Explains the folder to teammates |
| `.js-ts-conventions/overrides.json` | **user** | Created once, never overwritten |
| `.claude/rules/js-ts-conventions.md` | generated | Claude Code rule, scoped with `paths:` to JS/TS files |
| `.cursor/rules/js-ts-conventions.mdc` | generated | Cursor rule, `globs:` JS/TS files |

SHA protection: before writing, enforce compares each file with the hash recorded in the manifest. If the file was edited
by hand, it is skipped and reported (`SKIPPED`); `--force` overwrites. Files no longer generated are deleted only when
unedited. Commit everything except `REPORT.md`/`PLAN.md`/`audit.json` if the team prefers not to version audits.

Custom rules (`js-ts-conventions/<rule>`): `no-null`, `no-getters`, `readonly-props`, `naming`, `constant-case`,
`prefer-as-const-constants`, `filename-case`, `no-generic-error`, `no-deep-relative-imports`. Stock rules used:
`no-explicit-any`, `consistent-type-imports`, `explicit-module-boundary-types`, plus the type-aware `no-unsafe-*` family
when available.

Verified:

- Full cycle (generate → wire → ratchet → check): oxlint 1.88 and ESLint 10.12.
- `withConventions` wrapper: ESLint 8.57.
- Audit engine on real repos: oxlint 1.57 and 1.73, ESLint 9.39.

## Wiring oxlint

Append the generated file to `extends` in the unit's `.oxlintrc.json`, as the **last** entry:

```jsonc
{
  "extends": ["./.js-ts-conventions/oxlint.json"],
  // the repo's own settings stay as they are
  "plugins": ["import", "typescript", "unicorn"],
  "rules": { "...": "..." }
}
```

How oxlint merges it (verified):

- Convention rules sit in `overrides` blocks, and those beat the repo's top-level `rules` for matching files. A repo
  `"typescript/no-explicit-any": "warn"` then has no effect on the files the convention covers. `--check` lists it as
  a *note* to delete.
- The repo's own `overrides` entries are applied after the extended ones and **do** win. `--check` fails on those.
- `plugins` merge, so the conventions file doesn't switch off the repo's default plugins. The conventions file sets no
  `categories`, so the repo's category settings are untouched.
- `overrides[].files` in the conventions file resolve relative to the **extending** config's directory.
- `ignorePatterns` are **not** inherited through `extends`. That's why the generated files are written to pass the
  convention rules and `unicorn/no-null` themselves.

`oxlint.config.ts` (JS/TS configs) are not wired automatically. Import the JSON and add it to `extends` by hand.

## Wiring ESLint flat config

Wrap the whole export once. `withConventions` appends the convention blocks **after** the repo's configs, so convention severities
win unless something is appended after the wrapper.

```js
// eslint.config.mjs (repo root)
import withConventions from "./.js-ts-conventions/eslint.mjs";
export default withConventions([...existingConfigs]);
```

Common shapes:

```js
// typescript-eslint helper
export default withConventions(tseslint.config(a, b, c));
// ESLint defineConfig
export default withConventions(defineConfig([a, b, c]));
// re-exported shared preset
import base from "./packages/eslint-config/index.mjs";
export default withConventions(base);
// package config in a monorepo: pass its repo-relative directory
export default withConventions(tseslint.config(...), { unit: "apps/web" });
```

At runtime the wrapper:

- skips rules whose plugin namespace the repo never registers. Example: `@typescript-eslint/*` without
  typescript-eslint. The audit lists these under *Not run*.
- adds type-aware rules only when the repo config sets `parserOptions.projectService` or `project`.
- applies TypeScript rules exactly to the `files` globs the repo already parses with a TS parser, so no new files
  get linted.
- sets `emitDecoratorMetadata`/`experimentalDecorators` parser options when a tsconfig uses them. With these set,
  `consistent-type-imports` skips decorated files and NestJS DI keeps working.

## Monorepos

- **One root config** (single oxlint or ESLint unit): wire once at the root.
- **Per-package ESLint configs that import a shared preset** (`packages/eslint-config`): prefer wiring the preset.
  Wrap what it exports with `withConventions(...)` and no `unit` option; the unit is derived from the working directory
  (turbo runs lint per package). Otherwise wire each package config with its `unit`.
- **Per-package configs without a shared preset**: wire each one. enforce prints one step per config.
- Generated files always live in the repo-root `.js-ts-conventions/`; package configs import it relatively (e.g.
  `../../.js-ts-conventions/eslint.mjs`). `*.config.*` files are exempt from `alias-imports`, so this import is allowed.

## overrides.json

Repo-root `.js-ts-conventions/overrides.json`. Every exception needs a reason the user gave.

```json
{
  "disabled": { "readonly-props": "React props interfaces; revisit after the design-system migration" },
  "severity": { "explicit-types": "warn" },
  "exempt": { "no-null": ["src/**/infrastructure/**", "src/**/*.mapper.ts"] },
  "options": {
    "no-null": { "checkComparisons": false },
    "constant-case": { "allow": ["config"] },
    "filename-case": { "ignore": ["^README\\."] },
    "alias-imports": { "max_parent_depth": 2 }
  },
  "scope": { "typed-exceptions": true }
}
```

| Key | Effect |
|---|---|
| `disabled` | Preference removed from lint, agent rules and the audit (`➖` with the reason) |
| `severity` | `error` / `warn` / `off` instead of the level default (must → error, should → warn) |
| `exempt` | Repo-root-relative globs where the preference's rules are off (boundary code, generated code) |
| `options` | Merged into the custom rule's options (`alias-imports` takes `max_parent_depth`) |
| `scope` | Forces a DDD-scoped preference on in a repo without the folder layout |

Re-run `enforce.py` after every change; generated files and agent rules pick it up.

## Ratchet: freezing existing violations

Run after wiring: `python3 <skill>/scripts/enforce.py --ratchet`.

**ESLint ≥ 9.24** uses native bulk suppressions: `eslint . --suppress-rule <rule> …` per unit, written to
`<unit>/eslint-suppressions.json`. Counts are per file per rule: a frozen file can't gain more violations of that rule.
After fixing code, ESLint **fails** with "suppressions left that do not occur anymore" until you run
`eslint . --prune-suppressions` and commit the file. This step tightens the freeze automatically.

**ESLint < 9.24** has no suppressions. Upgrade, or temporarily set the failing preferences to `warn` in overrides.json.

**oxlint** has no native equivalent. `--ratchet` lints with the repo's real config and writes each file that has an
error-level convention violation into `.js-ts-conventions/legacy.json`. The regenerated oxlint config turns that rule off for
exactly those files. This is coarser than ESLint (per file, not per count). After fixing, re-run `--ratchet` to shrink
the list.

Warn-level preferences are never frozen; they don't fail lint.

## Conflicts and --check

`enforce.py --check` exits 1 when:

- a lint config is not wired.
- a repo setting wins over a convention rule. Examples: an `overrides` entry in `.oxlintrc.json` sets
  `"typescript/no-explicit-any": "warn"`, or an ESLint block after `withConventions` turns a convention rule off.
- a generated file was edited by hand.

It also prints *notes* that don't fail the check. A note is a repo setting that disagrees with the conventions but is
already overridden by them: oxlint top-level `rules`, or ESLint settings before the wrapper. Delete those so nobody
trusts them.

Resolve each conflict:

- If the repo setting is legacy, delete it.
- If the team really wants the exception, move it into overrides.json with the user's reason. It then shows up in the
  audit and agent rules instead of hiding in lint config.

`--check` is CI-friendly; suggest a `lint:conventions` script that runs it if the user wants drift detection.

## Type-aware rules

`no-any` adds `no-unsafe-assignment`, `no-unsafe-member-access`, `no-unsafe-call`, `no-unsafe-return` and
`no-unsafe-argument` when type information is available:

- **ESLint**: the repo config must set `parserOptions.projectService: true` (typescript-eslint); otherwise they are
  skipped.
- **oxlint**: `oxlint-tsgolint` must be a devDependency and the lint script must pass `--type-aware`. `--check`
  doesn't verify the flag; look at the `lint` script.

Enabling type-aware linting is a repo decision (slower lint). Offer it, don't do it unasked.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Parsing error: No tsconfigRootDir was set, and multiple candidate TSConfigRootDirs` | typescript-eslint with several configs in one ESLint 10 run | Add `parserOptions: { tsconfigRootDir: import.meta.dirname }` to each config. Not caused by this skill |
| `unknown field ...` from oxlint | Hand-edited generated file | Re-run `enforce.py --force` |
| Convention rule never fires in one package (ESLint) | Wired without `unit` and lint runs from the repo root | Pass `{ unit: "<dir>" }` |
| `Could not find plugin "@typescript-eslint"` | A config after `withConventions` references it | Move it before the wrapper, or register the plugin |
| Lint fails right after fixing code (ESLint) | Unused suppressions | `eslint . --prune-suppressions`, commit |
| oxlint reports convention rules in `.js-ts-conventions/` | Generated file edited, or an old plugin copy | Re-run `enforce.py` |
| Biome repo | Not supported by enforce v1 | Audit still works via `npx oxlint`; enforcement needs oxlint or ESLint |
| Legacy `.eslintrc*` | Flat config only | `npx @eslint/migrate-config .eslintrc.json`, then enforce |
